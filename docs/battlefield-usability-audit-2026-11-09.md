# 전장 행동 전반 사용성 진단

> 2026-11-09 · `codex/battlefield-usability-audit` · 기준 main [`e25b6eab`](https://github.com/lenope1214/Bindu/commit/e25b6eab5b4e64cca7ee5e0089d50e149588e9b9) · 게임 0.11.5
>
> 수정 전 진단 기록. 후속 [전체 수정 기록](battlefield-usability-implementation.md)에서 구현·검증을 추적한다. 실제 고객 VOC 원문·빈도·기기 정보는 제공받지 않았으므로 아래 항목을 고객 제보와 동일시하지 않는다.

## 먼저 볼 결론

가장 큰 문제는 **입력 의도와 실제 결과의 불일치**, **필요한 정보를 여는 경로의 단절**, **실수 후 복구 부족**이다. 설명을 더 쓰는 것만으로 해결되지 않는다.

특히 설정 뒤 단축키로 카드·새로고침·웨이브 상태가 바뀌고, 폰에서 일반 카드의 전체 설명을 읽는 경로가 끊긴다. 전투 중 정보창을 닫으면 다시 열 수 없고, 가까운 두 오브젝트 중 더 먼 쪽이 선택되기도 한다. 이 상태에서 오적용을 되돌리는 동작도 없다.

**총 50개: 재현 21 · 코드 확인 22 · 추가 검증 가설 7.** `재현`은 native Godot의 GUI 입력 또는 화면에서 확인한 현상, `코드`는 현행 구현에서 확인한 제약과 전문가 평가, `가설`은 추가 사용성 시험이 필요한 위험이다. 개선안·우선순위·완료 기준은 제안이며 승인된 제품 명세가 아니다. 발생률·영향 사용자 수·수정 공수는 추정하지 않았다.

## 점검 범위와 증거 읽는 법

macOS의 Godot 4.7.2 native 렌더러에서 PC 1280×720 / 글자 100%·130%, 폰 모의 2556×1179 / 글자 130%·안전 영역을 점검했다. 테스트 전용 Viewport에 마우스·키·ScreenTouch를 주입했다. OS 커서·전면 앱·개인 게임 저장·운영 서버는 사용하지 않았다.

상태 준비는 고정 fixture, 진단 행동은 실제 GUI 입력 경로를 사용했다. 전투 시간 확인은 프레임 갱신 함수를 명시적으로 진행했다. **사람이 아무 설명 없이 처음부터 플레이한 시험, 실기기 손맛, 실제 OS 앱 전환, 실통신 멀티플레이 증거는 아니다.**

- [실행 조건·로그·관찰값·캡처 목록](qa/2026-11-09-battlefield-usability/README.md)
- [PC 관찰값](qa/2026-11-09-battlefield-usability/actions-pc/observations.json), [폰 관찰값](qa/2026-11-09-battlefield-usability/actions-phone/observations.json), [PC 130% 관찰값](qa/2026-11-09-battlefield-usability/pc130/observations.json)
- [재현 도구](../tools/battlefield_usability_audit.gd). 관찰값의 ID를 각 항목에 병기했다.

`shot.gd`의 화면은 다양한 상태를 강제로 만든 레이아웃 자료다. 실제 플레이로 그 상태까지 도달했다는 증거가 아니다. 오래된 합성 카드·화면 밖에 준비한 오브젝트·검사 중 입력 모드 전환을 제품 버그로 세지 않았다. 자동 겹침 검사의 경고 수도 사용자 문제 수와 다르다.

## A. 의도와 다른 결과·복구 실패

### BF-01 · P1 · 재현 — 설정·도움말 뒤로 게임 단축키가 통과한다

- **상황·영향:** CHOOSE에서 `O→1`은 설정이 열린 채 PLACE로 전환한다. `H→Q`는 새로고침 1→0, `H→S`는 카드 선택 2회를 보류한다. READY에서 `O→Space`는 설정 뒤 웨이브를 시작 상태로 바꾼다. 설정을 닫을 때 사용자가 원하지 않은 상태를 마주한다.
- **개선:** 읽기 창이 입력을 소유하도록 공통 처리. 닫기·읽기 관련 키만 허용하고 게임 상태를 바꾸는 키는 소비한다.
- **완료 기준:** 각 창에서 카드·특성·새로고침·넘기기·시작 단축키를 눌러도 offer·남은 횟수·phase·bank가 동일하다. 창을 닫은 뒤 같은 키는 정상 작동한다.
- **근거:** `settings-number-key`, `help-reroll-key`, `settings-space-start`, `help-skip-key`; [설정 뒤 카드 선택 화면](qa/2026-11-09-battlefield-usability/actions-pc/08-settings-hidden-card-pick.png). 설정·도움말은 시뮬레이션을 멈춘다. **창 뒤에서 적이 계속 움직였다는 주장은 아니다.** [입력 분기](../scripts/features/interaction.gd#L227), [읽기 중 갱신 중지](../scripts/features/frame.gd#L248).

### BF-02 · P1 · 재현 — 폰의 일반 카드 전체 설명 접근 경로가 끊긴다

- **상황·영향:** `자세히`를 켜고 일반 카드를 0.45초 눌러도 전체 설명이 열리지 않는다. 손을 떼면 카드 들기로 넘어가 목록·정보창이 접힌다. 짧은 요약으로 결정을 강요받는다.
- **개선:** 일반 카드에도 명시적인 미리보기와 적용 행동을 제공. 특성 카드의 길게 눌러 읽기와 조작 규칙을 맞추거나, 카드별 정보 버튼을 둔다.
- **완료 기준:** 폰에서 세 카드 모두 소비·들기 없이 전체 효과·제약·상성을 끝까지 읽고 비교할 수 있다. 이후 적용도 기존 클릭·드래그 경로에서 1회만 실행된다.
- **근거:** `phone-card-detail-hold`: `detail_on=true`, `preview_card={}`, `side_visible=false`; release 후 PLACE. [누르는 중](qa/2026-11-09-battlefield-usability/actions-phone/20-phone-detail-hold.png), [손을 뗀 뒤](qa/2026-11-09-battlefield-usability/actions-phone/21-phone-detail-release.png). [일반 카드 터치](../scripts/features/cards.gd#L667), [미리보기 조건](../scripts/card_dock.gd#L350), [특성의 별도 길게 누르기](../scripts/features/perks.gd#L106).

### BF-03 · P1 · 재현 — 전투 중 닫은 정보창을 다시 열 수 없다

- **상황·영향:** 전투 중 오브젝트 정보의 `×`를 누르면 전역 닫힘 상태가 유지된다. 다른 오브젝트를 눌러도 정보가 안 열린다. `Z`도 WAVE에서 지원하지 않아 다음 카드 선택까지 핵심 정보 접근이 막힌다.
- **개선:** 호버로 자동 재등장하는 것은 막되, 명시적 오브젝트 선택에는 다시 열기. 또는 전투 중에도 보이는 정보창 복구 버튼 제공.
- **완료 기준:** WAVE·READY·CHOOSE 각각에서 닫기→다른 대상 선택→정보 열람이 한 동작으로 된다. 원치 않는 호버 재등장은 유지해서 막는다.
- **근거:** `wave-explicit-close-reopen`; [닫은 뒤 재선택](qa/2026-11-09-battlefield-usability/actions-phone/19-wave-inspector-cannot-reopen.png). [닫힘 상태](../scripts/card_dock.gd#L571), [복구 처리](../scripts/features/cards.gd#L157), [Z의 CHOOSE 제한](../scripts/features/interaction.gd#L341).

### BF-04 · P1 · 재현 — 가까운 두 오브젝트 중 더 먼 것이 선택된다

- **상황·영향:** 두 중심 간격 35, 누른 지점에서 첫 대상 24·둘째 11인 상황에서 첫 대상이 선택됐다. `_tower_at`은 거리순이 아니라 노드 순서의 첫 대상을 반환한다. 같은 판정이 카드 적용에도 사용된다.
- **개선:** 화면상 가까운 유효 대상을 우선. 동률·밀집 상태는 대상 강조와 선택 순환으로 해소한다.
- **완료 기준:** 생성 순서를 바꿔도 같은 화면 지점에서 같은 가까운 대상이 선택된다. 줌·폰·카드 적용에서 동일 규칙을 사용한다.
- **근거:** `nearby-target`; [재현 화면](qa/2026-11-09-battlefield-usability/actions-pc/07-nearer-object-not-selected.png), [대상 찾기](../scripts/features/interaction.gd#L930).

### BF-05 · P1 · 재현 — 오적용을 되돌릴 수 없고 Ctrl+Z는 자세히를 켠다

- **상황·영향:** 관통 적용 후 Ctrl+Z를 눌러도 강화 1·남은 선택 1은 그대로다. 대신 카드 자세히가 켜진다. 읽기·이동·적용이 가까운 입력에 묶여 있어 실수 비용이 높다.
- **개선:** 우선 수정키가 붙은 단축키의 오작동 차단과 적용 전 결과 확인을 개선한다. 되돌리기는 같은 쉬는 시간의 결정적 상태 복원 또는 새 정보 공개 전 취소로 별도 설계한다.
- **완료 기준:** Ctrl/Cmd+Z가 다른 기능을 실행하지 않는다. 복구 기능을 도입한다면 offer·RNG·남은 선택·기록까지 일관되게 복원하고 새 추첨을 탐색하는 이득이 없어야 한다.
- **근거:** `undo-after-card`; [적용 뒤 Ctrl+Z](qa/2026-11-09-battlefield-usability/actions-pc/03-applied-ctrl-z.png), [Z 처리](../scripts/features/interaction.gd#L341), [적용 후 새 선택 진행](../scripts/features/cards.gd#L734). **무제한 되돌리기는 랭크 규칙을 바꿀 수 있으므로 단순 UI 수정으로 바로 넣으면 안 된다.**

### BF-06 · P1 · 재현 — Esc 한 번이 정지가 아닐 수 있다

- **상황·영향:** 전투 중 정보를 읽다가 Esc를 누르면 정보창만 닫히고 전투는 계속된다. 두 번째 Esc에서 정지한다. 기술 조준 중에는 조준 취소가 우선이다. 급한 상황에서 정지 여부를 상태별로 기억해야 한다.
- **개선:** 정지 버튼은 항상 즉시 접근 가능하게 하고 키 역할을 명확히 표시한다. Esc의 단계 취소를 유지한다면 P·화면 버튼을 일관된 즉시 정지 경로로 가르친다.
- **완료 기준:** 선택·정보·조준 여부와 관계없이 한 동작으로 정지 가능. 화면만 보고 정지 여부를 확실히 알 수 있다.
- **근거:** `wave-first-escape`는 `paused=false`, `wave-second-escape`는 `true`; [입력 우선순위](../scripts/features/interaction.gd#L319).

### BF-07 · P1 · 재현 — 앱 전환 시 전투가 자동 정지하지 않는다

- **상황·영향:** 포커스 상실 알림 후 갱신에서 `wave_time` 0→0.05, `paused=false`. 다른 앱으로 이동한 동안 싱글 판을 잃을 수 있다. 실기기 백그라운드 실행 여부와는 별개다.
- **개선:** 싱글용 포커스 상실 정지 옵션을 노출하고 기본값을 결정한다. 온라인 판은 서버 진행 정책에 맞는 별도 안내가 필요하다.
- **완료 기준:** 옵션이 켜진 싱글 판은 포커스 상실 때 시간·피해·카운트다운이 멈추고, 돌아온 뒤 명시적 재개 전까지 유지된다.
- **근거:** `focus-out-wave`; [알림 처리](../scripts/app/session.gd#L515). 실제 OS 전환은 BF-47에서 추가 검증한다.

### BF-08 · P1 · 재현 — 오브젝트를 읽는 중 자동 시작한다

- **상황·영향:** READY에서 자동 시작 2초를 켜고 오브젝트 정보를 연 채 갱신하면 WAVE가 되고 선택이 해제된다. 드래그 중에는 대기하지만 정보 읽기는 대기로 취급하지 않는다.
- **개선:** 읽기·편집 중 자동 시작을 잠시 보류하거나, 해당 상태에서 바로 쓸 수 있는 카운트다운 정지 제공.
- **완료 기준:** 본문 스크롤·상세 열람·대상 비교 중 자동 시작 정책이 명확하고 사용자가 제어할 수 있다. 단순 호버로 무한 지연되지 않게 구분한다.
- **근거:** `auto-start-while-inspecting`의 `inspector_was_visible=true`, 최종 WAVE; [카운트다운 조건](../scripts/features/frame.gd#L250).

## B. 설치·이동·선택

### BF-09 · P2 · 재현 — 자동 조준 기본화 뒤에도 매번 방향 확정이 필요하다

- **상황·영향:** 새 속성을 빈 곳에 놓아도 AIM에 남아 추가 입력해야 설치된다. 기본 자동 조준을 알고 있는 사람에게 방향 단계의 필요가 불명확하다. 폰은 누르기·방향·확정 부담이 더 크다.
- **개선:** 자동 조준과 방향의 관계를 먼저 설명. 기본 방향으로 즉시 설치하고 원할 때 방향 선호를 편집하는 안을 비교 시험한다.
- **완료 기준:** 사용자가 방향의 실효를 설명할 수 있고, 보통 설치에 필요한 행동 수가 줄어든다. ±45도 선호와 동거리대 타겟 정책은 유지한다.
- **근거:** `new-placement-needs-direction`: `auto_aim=true`, AIM, 설치·선택 미소비; [폰 방향 단계](qa/2026-11-09-battlefield-usability/actions-phone/01-new-placement-direction.png), [배치 분기](../scripts/features/interaction.gd#L514). 방향은 타겟 선호에 영향을 주므로 완전히 무의미한 기능은 아니다. [MOD-13](features.md).

### BF-10 · P2 · 재현 — 방향 단계의 취소가 전체 취소로 오해될 수 있다

- **상황·영향:** 새 설치의 AIM에서 `취소` 한 번은 카드 복귀가 아니라 PLACE다. PLACE의 버튼은 이미 `카드 돌려놓기`로 구분돼 있지만, 첫 취소의 결과는 버튼 이름에서 알기 어렵다. 목록으로 돌아가려면 두 번 누른다.
- **개선:** AIM의 `취소`를 `위치 다시 정하기`처럼 결과로 표시. 전체 카드 취소가 자주 필요하면 별도 경로를 시험한다.
- **완료 기준:** 각 단계에서 취소 후 화면을 사용자가 예측한다. 이미 소비된 카드를 복구한다고 오해하지 않는다.
- **근거:** `cancel-once`, `cancel-twice`; [한 번 취소 후](qa/2026-11-09-battlefield-usability/actions-phone/02-cancel-once-still-carrying.png), [취소 분기](../scripts/features/interaction.gd#L848).

### BF-11 · P2 · 재현 — 카드를 든 뒤 무슨 카드인지 확인하기 어렵다

- **상황·영향:** 목록을 접고 빈 곳에 포인터가 있을 때 상태 줄은 `카드 놓는 중`만 표시한다. 대상에 올리기 전에는 이름·종류를 다시 확인하기 어렵다. 비교하다 돌아온 사용자가 기억에 의존한다.
- **개선:** 전장을 가리지 않는 작은 상태 칩에 카드 이름·레벨·남은 취소 동작 표시.
- **완료 기준:** 유효 대상 밖에서도 든 카드를 식별할 수 있다. 포인터를 따라다니는 큰 설명창은 추가하지 않는다.
- **근거:** [취소 후 카드 들기 화면](qa/2026-11-09-battlefield-usability/actions-pc/02-cancel-once-still-carrying.png), [상태 문구](../scripts/card_dock.gd#L538).

### BF-12 · P2 · 재현 — 선택한 오브젝트를 다시 누르면 방향 편집으로 바뀐다

- **상황·영향:** 첫 클릭은 선택·정보, 두 번째는 AIM이다. 정보를 다시 보려는 반복 탭이나 반응이 늦어 보일 때 재입력한 사용자가 편집에 들어갈 수 있다.
- **개선:** 반복 선택은 같은 상태를 유지하고 방향은 명시적 버튼으로 제공하는 안을 시험. 빠른 편집 조작은 별도로 유지할 수 있다.
- **완료 기준:** 정보 열람을 반복해도 위치·방향이 바뀌지 않는다. 편집 진입 상태는 즉시 식별된다.
- **근거:** `first-object-tap`, `second-object-tap`; [두 번째 클릭](qa/2026-11-09-battlefield-usability/actions-phone/04-second-tap-direction.png), [짧은 클릭 분기](../scripts/features/interaction.gd#L673).

### BF-13 · P2 · 재현 — 읽으려고 누르고 있어도 이동이 시작된다

- **상황·영향:** 움직이지 않고 0.4초 눌러도 `dragging=true`. 특성에서는 길게 누르기가 자세히 읽기인데 전장에서는 이동이다. 손 떨림이 곧 재배치로 이어질 수 있다.
- **개선:** 이동은 명확한 이동량으로 시작하거나 편집 손잡이 제공. 길게 누르기를 유지하면 진입 전 피드백을 둔다.
- **완료 기준:** 정보 확인을 위한 정지 터치가 위치 변경으로 이어지지 않는다. 이동 중 취소와 확정은 구분된다.
- **근거:** `long-press-object`; [길게 누르기](qa/2026-11-09-battlefield-usability/actions-phone/05-long-press-starts-moving.png), [350ms 기준](../scripts/features/interaction.gd#L639).

### BF-14 · P2 · 재현 — 확대하려던 휠이 방향을 바꾼다

- **상황·영향:** 선택 대상 위 휠은 방향 회전, 다른 곳 휠은 확대다. 재현에서 방향은 바뀌고 확대는 1.0이었다. 이미 선택돼 있는지 기억해야 같은 제스처 결과를 예측한다.
- **개선:** 회전에 수정키 또는 명시적 편집 모드를 요구하는 안을 검토. 회전량·방향 복구도 가까이 제공한다.
- **완료 기준:** 전장 확대를 위해 굴린 휠이 배치를 수정하지 않는다. 트랙패드의 작은 입력도 포함한다.
- **근거:** `wheel-on-selected`; [휠 처리](../scripts/features/interaction.gd#L93).

### BF-15 · P2 · 코드 — 무효 이동의 구체적 이유를 이동 중 읽기 어렵다

- **상황·영향:** 추가 검토에서 드래그 중 무효 오브젝트의 빨간 고리는 이미 있음을 확인했다. 구체적 거절 이유는 release 뒤 알림으로 나오며 하나라도 무효면 그룹 전체를 원복한다. 혼잡한 배치를 옮길 때 실패 이유·실패 대상·도착 가능 지점을 찾는 시행착오가 생긴다.
- **개선:** 이동 중 유효·무효와 충돌 대상을 표시. 그룹 중 실패 원인이 된 오브젝트도 구분한다.
- **완료 기준:** 손을 떼기 전에 성공 여부와 이유를 알 수 있고, 무효 이동은 기존처럼 안전하게 원복된다.
- **근거:** [드래그 갱신·확정](../scripts/features/interaction.gd#L639), [배치 거절 정책](../scripts/domain/placement_policy.gd).

### BF-16 · P2 · 코드 — 터치에서 다중 선택 추가·제거가 드러나지 않는다

- **상황·영향:** 영역 선택은 가능하지만 기존 선택에 더하기·빼기는 Shift/Ctrl/Meta에 묶여 있다. 폰에서 떨어진 몇 개만 골라 이동하기가 어렵다.
- **개선:** 선택 모드와 추가·제거·전체 선택을 화면에서 제공한다.
- **완료 기준:** 키보드 없이 떨어진 대상 3개 선택→1개 제외→그룹 이동이 가능하다.
- **근거:** [영역 선택의 수정키 조건](../scripts/features/interaction.gd#L749), [선택 추가 분기](../scripts/features/interaction.gd#L673). 실제 손가락 수행 시간은 미측정.

### BF-17 · P2 · 코드 — 그룹 방향을 한 번에 바꿀 수 없다

- **상황·영향:** 그룹 이동은 지원하지만 방향 버튼은 선택 1개일 때만 노출된다. 새 길목에 맞춰 여러 개를 조정할 때 각각 선택·회전·복귀해야 한다.
- **개선:** 공통 방향·상대 회전 등 가능한 의미를 먼저 정하고 그룹 편집을 제공한다.
- **완료 기준:** 그룹 방향 조정 결과를 미리 보고 취소할 수 있다. 각 오브젝트의 자동 조준 선호가 어떻게 바뀌는지 명확하다.
- **근거:** [방향 버튼 조건](../scripts/card_dock.gd#L673), [단일 선택 편집](../scripts/features/interaction.gd#L776).

### BF-18 · P2 · 코드 — 선택·끌기 기준이 화면 크기와 줌에 따라 다르게 느껴질 수 있다

- **상황·영향:** 오브젝트 선택 반경 30과 오브젝트 드래그 전환 12는 월드 좌표다. 카드 드래그의 12는 화면 좌표다. 같은 손 움직임이 줌·기기·행동에 따라 다르게 해석된다.
- **개선:** 터치 최소 표적과 제스처 임계값을 화면 좌표 기준으로 통일하고 밀집 시 선택 정책을 보완한다.
- **완료 기준:** 같은 물리적 터치에서 줌별 오탭·의도치 않은 드래그 비율을 측정하고 감소시킨다. 월드 오브젝트 크기·카메라 배율은 유지한다.
- **근거:** [대상 반경](../scripts/features/interaction.gd#L930), [오브젝트 드래그](../scripts/features/interaction.gd#L639), [카드 제스처](../scripts/card_dock.gd#L332). 물리 크기별 오탭 발생률은 가설이다.

### BF-19 · P2 · 코드 — 키보드만으로 배치·상세 조작을 끝낼 수 없다

- **상황·영향:** 카드 선택 단축키는 있으나 전장 위치·대상 지정은 포인터에 의존하고 주요 버튼은 `FOCUS_NONE`이다. 키보드 사용자는 입력 방식을 계속 바꿔야 한다.
- **개선:** 대상 순환, 선택 확인, 취소, 위치 이동, 방향 조정에 일관된 키보드 경로 설계.
- **완료 기준:** 카드 읽기→대상 선택→적용→취소→웨이브 시작→정지까지 포인터 없이 수행한다. 포커스 위치도 보여야 한다.
- **근거:** [UI 버튼 구성](../scripts/features/ui_shell.gd), [전장 입력](../scripts/features/interaction.gd). 스크린리더·게임패드 지원 여부까지 확인한 결과는 아니다.

## C. 정보 읽기·선택 판단

### BF-20 · P1 · 재현 — 폰에서 카드와 정보를 함께 보면 본문 공간이 거의 없다

- **상황·영향:** 유효한 3속성 오브젝트 선택 시 폰 정보창 높이 약 143.6, 스크롤 본문 높이 79, 내용 그림의 최소 높이 400이었다. 제목·속성 일부만 보고 수치는 여러 번 스크롤해야 한다.
- **개선:** 선택 판단 중 필요한 핵심 수치는 짧은 고정 요약에 두고, 전체 정보는 명시적 확장으로 제공. 카드 줄과 정보창의 동시 표시 구조를 조정한다.
- **완료 기준:** 폰 130%에서 대상 이름·속성·주요 피해·공격 빈도·적용 결과를 첫 화면에서 판단 가능. 전장 월드 크기나 카메라 줌을 줄여 공간을 만들지 않는다.
- **근거:** `inspector-with-cards`; [폰](qa/2026-11-09-battlefield-usability/actions-phone/22-inspector-with-cards.png), [PC](qa/2026-11-09-battlefield-usability/actions-pc/22-inspector-with-cards.png), [공간 계산](../scripts/card_dock.gd#L686).

### BF-21 · P2 · 코드 — 수치를 보려면 큰 공격 예시부터 지나가야 한다

- **상황·영향:** 정보창 순서가 제목·속성→높이 180 공격 예시→수치 타일이다. 이미 아는 공격을 반복 확인할 때도 핵심 수치가 아래로 밀린다.
- **개선:** 숫자·제약을 먼저, 공격 예시는 접을 수 있게 제공. 새 공격을 처음 볼 때 예시를 여는 정책도 비교한다.
- **완료 기준:** 익숙한 오브젝트의 비교 수치를 스크롤 없이 읽고, 원할 때 예시를 다시 볼 수 있다.
- **근거:** [정보창 그리기 순서](../scripts/info_panel.gd#L350), [공격 예시](../scripts/attack_preview.gd). BF-20은 외부 패널 공간, 이 항목은 정보창 내부 순서의 문제다.

### BF-22 · P2 · 재현 — 넘기기 전환 때 정보창과 진행 표시가 겹친다

- **상황·영향:** 폰에서 선택 중 본 정보가 유지된 채 넘기면 정보창과 `넘기는 중…` 표시가 겹치는 구성을 재현했다. 진행 상태 확인·멈추기 표적 식별이 어려워진다.
- **개선:** 넘기기 배지를 정보창 회피 영역에 포함하거나 전환 시 정보를 접고 복구 경로를 둔다.
- **완료 기준:** 정보창 자동 위치·고정 위치·접힘 상태에서 넘기기 배지와 본문이 겹치지 않는다.
- **근거:** [폰 넘기기 직후](qa/2026-11-09-battlefield-usability/actions-phone/18-skip-bank.png), 같은 이름의 `UI OVERLAP` 로그; [정보창 회피 대상](../scripts/card_dock.gd#L686). 자동 경고 전체를 버그로 센 결과는 아니다.

### BF-23 · P2 · 코드 — 오브젝트 선택을 유지하면 카드 호버 미리보기로 바로 전환되지 않는다

- **상황·영향:** 선택 대상 정보가 우선이고 `inspected_tower`가 있으면 `preview_card()`가 빈 값을 반환한다. 대상 성능과 새 카드 효과를 오가며 비교할 때 선택 해제라는 중간 동작이 필요하다.
- **개선:** 선택 유지와 일시적 카드 미리보기를 분리하거나 비교 버튼 제공. 선택한 대상에 대한 적용 전후 비교가 특히 유용하다.
- **완료 기준:** 같은 대상을 유지한 채 세 카드의 효과를 비교하고 원래 정보를 복구한다.
- **근거:** [카드 미리보기 조건](../scripts/card_dock.gd#L350), [선택 우선 정보](../scripts/card_dock.gd#L588).

### BF-24 · P1 · 재현 — 카드 요약의 핵심 효과가 말줄임된다

- **상황·영향:** 폰 130%에서 협공 요약이 `그 구체 최대…`에서 끝난다. 효과량을 모른 채 비교하게 된다. 일반 카드 상세 접근 문제(BF-02)와 겹치면 우회 경로도 없다.
- **개선:** 요약에는 대상·핵심 효과·수치를 우선 배치하고 부수 조건을 상세로 옮긴다. 핵심 절은 말줄임하지 않는다.
- **완료 기준:** 실제 카드 풀 전수에서 선택을 바꿀 수 있는 수치·고정·대가가 요약에 보인다. 핵심을 자르지 않는 축약 기준이 있다.
- **근거:** [폰 카드 화면](qa/2026-11-09-battlefield-usability/phone/cards_1.3_touch_phone.png), [2줄 말줄임](../scripts/card_dock.gd#L792). 이 말줄임은 자동 UI 검사에서 `UI ok`였다.

### BF-25 · P2 · 코드 — 여러 적용 대상 중 무엇을 고를지 비교 비용이 높다

- **상황·영향:** 적용 가능 고리와 대상 위 효과 미리보기는 있지만 여러 대상의 변경량을 나란히 비교하는 경로는 없다. 하나씩 왕복하며 읽고 기억해야 한다.
- **개선:** 선택한 카드 기준으로 대상별 핵심 변화만 짧게 비교. 계산 가능한 변화와 실전 기여 추정은 구분한다.
- **완료 기준:** 대상 5개 중 적용 가능·새 상성·핵심 증감의 차이를 한 화면에서 비교한다. 추정 DPS를 확정 성능처럼 제시하지 않는다.
- **근거:** [적용 대상 판정](../scripts/card_dock.gd#L359), [대상 위 설명](../scripts/features/field_view.gd). 실제 판단 시간 감소는 후속 시험 대상.

### BF-26 · P2 · 코드 — 나가기 전 저장 경계를 평소 화면에서 알기 어렵다

- **상황·영향:** 저장은 쉬는 시간에 이뤄지고 웨이브 중 나가면 앞 쉬는 시간으로 돌아간다. 안내는 일시정지 문구에 있다. 종료·업무 전환 전까지 복원 범위를 확인하기 어렵다.
- **개선:** 지속적인 큰 배너 대신 저장 완료와 복원 지점을 짧게 확인할 수 있게 제공. 시작 화면 복귀 행동에도 해당 결과를 표시한다.
- **완료 기준:** 게임 중 언제든 마지막 저장·나가면 돌아올 지점을 확인한다. 멀티 판 저장 여부도 혼동하지 않는다.
- **근거:** [저장 조건](../scripts/features/persistence.gd#L5), [나가기 안내](../scripts/features/run_flow.gd#L647). 저장 손실을 재현했다는 뜻은 아니다.

### BF-27 · P2 · 코드 — 기본 자동 조준과 조작 설명의 개념이 맞지 않는다

- **상황·영향:** 최신 규칙은 위협 우선·방향 선호·예측 조준인데 도움말은 여전히 `쏠 방향` 중심이고 README에는 과거 자동 조준 강화 카드 설명이 남아 있다. 배치를 잘못 이해하면 방향을 바꿨는데 다른 적을 겨누는 이유를 알기 어렵다.
- **개선:** `위험한 구체 우선, 비슷한 위험도면 정한 방향 우선`을 게임 안 기본 설명과 실제 조준 표시로 연결한다.
- **완료 기준:** 빈 사거리·위험 대상·방향 선호·예측 조준의 대표 장면에서 설명과 실제 결과가 일치한다. 오래된 반응 카드 설명도 정리한다.
- **근거:** [MOD-13 현행 규칙](features.md), [도움말](../scripts/features/run_flow.gd#L24), [기준 main의 이전 README](https://github.com/lenope1214/Bindu/blob/e25b6eab5b4e64cca7ee5e0089d50e149588e9b9/README.md#L103).

### BF-28 · P2 · 코드 — 거절 후 다음 행동을 찾는 비용이 크다

- **상황·영향:** 무효 조합·상한·위치에는 이유 알림이 있고 미소비도 보장된다. 그러나 다른 대상을 찾거나 제한을 해소하는 경로는 사용자가 다시 탐색해야 한다. 불가 이유가 순간 알림에만 남는 경우 반복 시도하게 된다.
- **개선:** 불가 대상 옆에 지속 이유와 가능한 대안 표시. `다른 오브젝트에 적용 가능 N개`처럼 사실에 기반한 안내를 제공한다.
- **완료 기준:** 오류 뒤 이유를 재확인하고 유효 대상에 바로 접근한다. 잘못된 대상을 눌러도 기존처럼 횟수는 소비하지 않는다.
- **근거:** [적용 거절](../scripts/features/interaction.gd#L514), [거절 이유](../scripts/features/interaction.gd#L571), [카드 제약](../scripts/features/cards.gd#L868).

### BF-29 · P2 · 코드 — 새로고침 버튼의 뜻·소진 상태를 찾기 어렵다

- **상황·영향:** 본문 라벨은 아이콘과 숫자뿐이며 횟수가 0이면 버튼이 사라진다. PC는 툴팁이 있지만 폰은 실행 전 의미를 읽기 어렵고, 다 쓴 것인지 기능 자체가 없는 것인지 구분이 약하다.
- **개선:** `새로고침 1` 라벨 또는 터치 설명을 제공하고 소진 시 비활성 상태·이유 유지.
- **완료 기준:** 첫 이용자가 버튼의 결과와 남은 횟수를 실행 전에 설명한다. 0·1·보너스 횟수 상태가 구분된다.
- **근거:** [카드 화면](qa/2026-11-09-battlefield-usability/phone/cards_1.3_touch_phone.png), [노출 조건](../scripts/features/cards.gd#L654).

## D. 진행·정지·전투 기술

### BF-30 · P2 · 재현 — 웨이브 수 선택이 순환 버튼이라 원하는 값으로 돌아가기 번거롭다

- **상황·영향:** 버튼을 누를 때 3→5→10→1→3으로 순환한다. 3에서 1로 바꾸려면 세 번, 실수로 지나치면 다시 돌아야 한다.
- **개선:** 1·3·5·10을 직접 고르는 작은 메뉴나 분할 선택 제공. 값을 바꾸는 것과 실행을 계속 분리한다.
- **완료 기준:** 원하는 횟수를 한 번의 선택으로 정하고 실제 연속 진행 수가 항상 눈에 보인다.
- **근거:** `skip-cycle`; [순환 구현](../scripts/features/run_flow.gd#L252).

### BF-31 · P2 · 코드 — 넘기기가 전투 생략처럼 읽힐 수 있다

- **상황·영향:** `넘기기`는 전투를 생략하는 것이 아니라 카드 선택을 미루고 실제 웨이브를 연속 진행한다. 뜻은 툴팁·알림에 있으나 폰에서 누르기 전에는 확인하기 어렵다.
- **개선:** `3웨이브 연속 진행`·`카드 선택은 나중에`처럼 결과가 드러나는 명칭으로 시험한다.
- **완료 기준:** 사용자가 실행 전에 적·체력 손실이 정상 적용됨과 카드 보류를 이해한다.
- **근거:** [넘기기 동작](../scripts/features/run_flow.gd#L158), [버튼 설명](../scripts/features/run_flow.gd#L260).

### BF-32 · P1 · 코드 — 넘기기 멈춤은 현재 웨이브를 즉시 멈추지 않는다

- **상황·영향:** WAVE에서 멈추기는 `skip_stop`을 예약하고 현재 웨이브가 끝나야 적용된다. READY에서는 바로 끝난다. 위험할 때 `멈추기`를 눌러도 계속 공격받는 의미 차이가 크다.
- **개선:** `이번 웨이브 뒤 멈춤`을 실행 전부터 명시하고 즉시 정지를 인접 제공한다.
- **완료 기준:** 사용자가 연속 진행 예약 취소와 즉시 정지를 구분한다. 멈춤 예약의 켜짐·꺼짐도 지속 표시된다.
- **근거:** [멈춤 분기](../scripts/features/run_flow.gd#L241), [넘기기 표시](../scripts/features/run_flow.gd#L260).

### BF-33 · P2 · 코드 — 보류한 선택을 몰아서 처리하는 비용을 미리 알기 어렵다

- **상황·영향:** 특성→카드 순으로 누적 보상을 한 번씩 처리한다. 연속 진행을 많이 할수록 몇 단계가 남았고 어느 종류를 처리 중인지 파악하는 비용이 커진다.
- **개선:** 특성·카드·새로고침의 보류 내역과 처리 순서·남은 단계를 한곳에 제공. 무작위 결과를 미리 보여주는 식으로 규칙을 바꾸지는 않는다.
- **완료 기준:** 10웨이브 진행 후 사용자가 남은 종류·횟수·다음 행동을 설명하고, 중단·이어하기 후에도 동일하다.
- **근거:** [보류 누적·복구](../scripts/features/run_flow.gd#L180), [보상 순서](../scripts/features/run_flow.gd#L219).

### BF-34 · P1 · 코드 — 폰에서 긴급 정지가 접힌 설정 안에 있다

- **상황·영향:** 기본 접힘 버튼 줄에 일시정지가 들어간다. 키보드가 없는 폰은 펼치기→정지 두 동작이 필요하다. 선택·기술·피해가 겹칠 때 도달 비용이 크다.
- **개선:** 전투 중 정지는 항상 노출. 배속·음량·자동 시작 설정은 별도 접힘 유지 가능.
- **완료 기준:** 모든 전투·편집·정보 상태에서 한 번의 터치로 즉시 정지한다. 노치·오른손·왼손 접근도 검증한다.
- **근거:** [버튼 줄 구성](../scripts/features/ui_shell.gd#L279), [버튼 줄 배치](../scripts/card_dock.gd#L376), [터치 도움말](../scripts/features/run_flow.gd#L51).

### BF-35 · P2 · 재현 — Space는 시작 뒤에는 가속이다

- **상황·영향:** READY에서는 시작, WAVE에서는 1→선택 배속이다. 정지 습관으로 Space를 누르거나 시작 입력을 반복하면 더 빨라진다.
- **개선:** 상태별 키 결과를 가까이 표시하고 시작 직후 중복 입력 방지 여부 검토. 정지는 한 동작 경로로 고정한다.
- **완료 기준:** 시작·정지·가속을 사용자가 혼동하지 않는다. 길게 누르기·연속 누르기에서 원치 않는 가속이 없다.
- **근거:** `space-during-wave`: 1→2, `paused=false`; [Space 분기](../scripts/features/interaction.gd#L355).

### BF-36 · P2 · 재현 — 기술 조준 중에도 전투가 진행된다

- **상황·영향:** 붙잡기를 고르고 쓰기 좋은 곳을 찾는 동안 게임 시간이 증가했다. 빠른 배속일수록 조준·문구 이해에 쓸 실제 시간이 짧다.
- **개선:** 조준 중 일시 감속·정지 옵션을 시험하거나, 배속을 쉽게 해제하는 경로를 제공한다. 전투 난도에 영향을 주므로 모드별 결정을 남긴다.
- **완료 기준:** 사용자가 기술의 대상·범위를 확인한 뒤 의도한 곳에 적용한다. 취소는 쿨다운을 쓰지 않고 조준 중 속도 정책이 예측 가능하다.
- **근거:** `skill-aim-time`; [기술 준비](../scripts/features/abilities.gd#L130), [프레임 진행](../scripts/features/frame.gd#L266).

### BF-37 · P2 · 코드 — 기술 버튼 이름만으로 효과·대상을 알기 어렵다

- **상황·영향:** 버튼은 `집중`·`붙잡기`·`낙인` 또는 남은 초다. 전체 설명은 툴팁, 짧은 효과 설명은 조준에 들어간 뒤 알림이다. 폰은 누르기 전에 뜻을 비교하기 어렵다.
- **개선:** 버튼에 `공격 속도↑`·`구체 멈춤`·`받는 피해↑`와 대상 유형을 함께 표현한다.
- **완료 기준:** 처음 본 기술의 대상·핵심 효과·사용 준비 여부를 실제 발동 전에 구분한다.
- **근거:** [기술 버튼 문구·툴팁](../scripts/features/abilities.gd#L165), [짧은 설명](../scripts/skill.gd#L25).

### BF-38 · P2 · 코드 — 쿨다운 초가 실제 기다릴 초와 다르다

- **상황·영향:** 쿨다운은 게임 시간으로 줄어든다. x8에서 `8초`는 대략 실제 1초다. 웨이브 시작 때는 다시 초기화된다. 숫자만 보면 다음 사용 시점을 예측하기 어렵다.
- **개선:** 게임 시간임과 웨이브 재충전을 알리고, 원형 진행이나 준비 신호를 함께 제공한다.
- **완료 기준:** 1·2·8배속에서 사용자가 재사용 가능 시점을 구분한다. 실제 시간 표시를 추가하면 게임 시간과 명칭을 혼동하지 않는다.
- **근거:** [기술 갱신](../scripts/features/abilities.gd#L115), [웨이브 초기화](../scripts/features/run_flow.gd#L353), [기술 규칙](../scripts/skill.gd#L1).

### BF-39 · P2 · 코드 — 기술 실패 이유를 적용한 뒤에 배우게 된다

- **상황·영향:** 주변 구체 없음·집중 대상 없음·붙잡기 면역은 실패 후 알림으로 설명한다. 쿨다운 미소비는 좋지만 급한 상황에서 여러 번 눌러야 조건을 알아낼 수 있다.
- **개선:** 조준 중 실제 유효 대상과 면역·미적용 대상을 구분하고 적용 예상 수 표시.
- **완료 기준:** 손을 떼거나 클릭하기 전에 적용 대상·무효 이유를 확인한다. 완전 무효 기술은 기존처럼 자원을 소비하지 않는다.
- **근거:** `hold-empty-area`는 `cooldown=0`, 조준 유지·이유 알림; [기술 적용 실패](../scripts/features/abilities.gd#L145), [붙잡기 대상](../scripts/skill.gd#L71). 면역 실기기 재현은 수행하지 않았다.

### BF-40 · P2 · 코드 — 기술 자동 사용 여부가 전투 버튼에서 드러나지 않는다

- **상황·영향:** 설정의 자동 사용이 켜지면 조건에 맞춰 기술이 소모된다. 버튼에는 수동·자동 상태가 표시되지 않아, 누르지 않았는데 쿨다운이 생기는 이유를 찾기 어렵다.
- **개선:** 기술 영역에 자동 상태와 바로 끄기를 표시. 자동 발동에는 짧은 원인 피드백 제공.

5. **판단과 실기기 확인:** BF-36–50. 기술·DPS의 의미를 정리하고 폰·두 기기·후반 부하에서 평가한다.

각 묶음은 작은 변경으로 나누고 동일 시드·상태·해상도·배율의 전후 캡처를 남긴다. 현재 전장 월드 크기·사거리·카메라 줌·자동 조준 우선순위·콘텐츠·밸런스 수치는 사용성 개선을 위한 공간 확보 수단으로 변경하지 않는다. 되돌리기·조준 감속처럼 규칙에 영향이 있는 제안은 별도 결정이 필요하다.

## 이미 확인된 보호 장치

- 무효 대상·빈 기술 영역에서 횟수나 쿨다운을 소비하지 않는다. 이번 `hold-empty-area`도 쿨다운 0이었다.
- 이전 진단에서 고친 정지 중 게임 단축키 차단과 협동 소유권 보호가 현행 코드에 있다. 이번 BF-01은 일시정지가 아닌 설정·도움말의 입력 경계다.
- 도움말·설정은 전투 시뮬레이션을 멈춘다. 이를 전투가 뒤에서 계속되는 문제로 쓰지 않았다.
- 첫 일반 판 안내의 기존 검사도 폰 130%에서 실패 0. 이것이 처음 보는 사람의 이해도 검증을 대신하지는 않는다.
- 카드 들기 중에는 목록이 접히고 전장 카메라는 고정된다. 개선 과정에서 이 동작을 보존한다.

## VOC와 연결할 후속 과제

실제 제보를 받을 때 `행동 직전 상태 → 의도 → 입력 → 실제 결과 → 복구 시도`, 기기·빌드·배율·배속·싱글/멀티를 함께 기록한다. 위 BF 번호에 연결하되 일치하지 않으면 새 원인으로 분류한다. 제보 수만으로 원인을 합치지 않는다.

대표 과제는 카드 세 장 비교, 특정 대상에 적용, 취소, 밀집 대상 선택, 그룹 이동, 약한 배치 찾기, 기술 사용, 즉시 정지, 연속 진행 중단, 나가기·복귀다. 과제별 성공·오실행·되돌림·도움말 의존·입력 수·시간을 같은 조건의 개선 전후로 비교한다. 목표 숫자는 기초 측정 뒤 정한다.
