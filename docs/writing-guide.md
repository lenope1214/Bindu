# Bindu 문체 가이드

플레이어가 읽는 카드 요약·상세·도감의 효과 설명에 적용한다. 코드 주석·기술 문서·커밋 메시지는 대상이 아니다. 패치노트의 내용 기준은 [CHANGELOG 작성 규칙](changelog-rules.md)을 함께 따른다.

## 종결형

- 효과·조건·예외를 설명하는 문장은 해요체로 쓴다. `~해요.`, `~돼요.`, `~예요.`, `~할 수 있어요.`로 끝낸다. 요약과 상세의 문체는 같다.
- 수치·이름·라벨은 생략형을 허용한다. 예: `공격 속도 +15%`, `오브젝트당 1회`, `못 넣는 강화: 벽·혼불`. 문장을 수치 라벨로 위장해 `~됨`, `~없음`, `~한다`로 끝내지 않는다.
- 조작을 요청할 때는 `~하세요.`로 쓴다. 버튼은 `자세히`, `확정`처럼 행동 이름을 쓴다.
- 완결된 문장 끝에 마침표를 쓴다. 수치만 있는 줄·괄호 속 수치·라벨에는 생략할 수 있다. 설명 중 괄호는 조건과 수치를 보충할 때만 쓴다.

## 정보와 용어

- 결과를 먼저 설명하되, 발동 조건·대상·확률·시간·거리·상한·감쇠·대가·적용 제외를 빼거나 바꾸지 않는다.
- 요약은 기존 정보 범위를 유지한다. 상세에 있는 모든 수치를 요약에 옮길 필요는 없지만, 선택을 바꾸는 조건이나 대가를 줄이거나 숨기지 않는다.
- 숫자·단위·부호·배율·범위·`{수치 키}`를 그대로 보존한다. `절반`, `한 번만`, `누가 잡든`, `가장 강한 하나만` 같은 조건도 수치만큼 중요하다.
- 화면에 있는 이름을 쓴다. `구체`, `오브젝트`, `속성`, `공격방식`, `강화`, `연계`, `발동`, `특성`을 임의의 동의어로 바꾸지 않는다. 효과·특징의 이름도 유지한다.
- 한 문장에는 한 효과나 연결된 조건을 담는다. 수식어·홍보 문구·불필요한 인사말을 넣지 않는다.

## 교정 예

- `공격이 1개 더 ~~나간다~~ **나가요.**`
- `벽·투척 장판에는 ~~못 넣음~~ **못 넣어요.**`
- `공격 속도 +15%`는 수치 라벨이므로 그대로 둔다.

## 원본과 화면 검증

- 속성: `scripts/elem.gd`의 BRIEF·RIDER·TRAIT·상성 설명.
- 공격방식·강화·연계·발동: `scripts/pattern.gd`의 정의·BRIEF·적용 제외 안내.
- 카드별 별도 설명·특성: `scripts/main.gd`. 도크·상세·도감이 같은 원본을 쓰는지 확인한다.
- 온라인 `perk_desc` 덮어쓰기는 별도 원문이다. 운영자가 이 가이드를 따라 작성해야 한다.
- 문체를 바꾼 뒤 원문과 숫자·수치 키·조건을 대조한다. 교정 내역에는 변경을 인라인으로 표시한다.
- PC 100%·130%, 폰 안전 영역·터치 모의 130%, 태블릿 비율·터치 모의 130%에서 전체 카드의 요약과 상세를 확인한다.
- 자동 줄바꿈을 사용한다. 폭을 맞추려고 조건·수치를 지우거나 폰트를 줄이지 않는다. 도크의 두 줄 요약은 말줄임을 허용하되, 설명창의 전체 원문은 스크롤 끝까지 읽을 수 있어야 한다.
- 한글 깨짐·고립된 종결어미·숫자와 단위 분리·버튼과의 겹침·상세 마지막 줄 잘림을 확인한다. 실제 기기 검증과 데스크톱 모의를 구분한다.
