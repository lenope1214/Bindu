# 첫 실행 안내와 기본 카드 설명 개선안

상태: 제안·미구현. 2026-11-03, main `0c8e15b` 기준 소스 검토.
대상: 첫 실행부터 첫 웨이브까지의 신규 플레이어. 구현 전 논의용 PR이다.

## 판정

첫 실행의 연속 설명을 행동 안내로 바꾸고, 간소화 카드에는 효과를 이해할 수 있는 짧은 문장을 남긴다.
전체 설명을 기본으로 켜거나 용어를 더 줄이는 방식은 권장하지 않는다.

성공 기준은 '읽은 페이지 수'가 아니라 '도움 없이 카드 효과를 예상하고 설치·방향 지정·첫 웨이브 시작을 수행하는가'다.

## 확인된 사실과 아직 모르는 것

- `scripts/tutorial.gd`의 FIRST는 goal·place·cards·stack 4개 항목이다. 각각 3장이므로 첫 실행에 총 12장이 이어진다.
- `scripts/main.gd`의 `_tut_tick()`은 첫 실행에 이를 자동으로 띄운다. 이후 이벤트 항목도 쉬는 시간에 자동으로 열고 판을 일시정지한다.
- `_guide()`는 긴 안내를 최대 3개 누적하고, 최초에는 안내를 끄는 방법도 덧붙인다. `_guide()` 호출은 튜토리얼 이벤트도 등록하므로 같은 개념을 여러 안내 층에서 만날 수 있다.
- `_card_simple()`은 속성의 기본 설명을 효과 이름 두 개와 '적중·형태' 꼬리표로 바꾼다. 텍스트는 짧지만 그 결과를 모르는 사람은 의미를 추론해야 한다.
- 첫 판의 카드 종류 단계적 해금은 이미 있다. 속성만 시작해 공격방식 3·강화 4·발동 5·연계와 대격변 6웨이브에 열린다. 새로 만들 필요가 없다.
- VOC의 발생 빈도, 실제 첫 설치 시간, 설명 건너뛰기율, 카드 오해 사례는 미측정이다. 정보 과부하와 용어 불명확성이 원인이라는 판단은 소스와 VOC에 근거한 가설이다.

## 1. 첫 실행: 읽기 전에 한 번 해보기

첫 실행은 목표 한 문장과 '플레이하며 배우기', 선택적인 '자세한 설명' 진입만 보여 준다.
권장 목표 문구: '다가오는 구체를 막아 중앙을 지키세요.'
기존 12장 자료는 튜토리얼 목록에 남겨 다시 볼 수 있게 한다.

일반 판을 시작하면 현재 단계에서 할 행동 하나만 안내한다.

| 실제 상태 | 보여줄 행동 | 다음 안내로 넘어가는 조건 |
|---|---|---|
| 카드 고르기 | '카드를 하나 고르세요.' | PC: 카드 확정. 터치: 미리보기 후 확정 |
| 터치 카드 미리보기 | '선택한 카드를 적용하세요.' | 적용 버튼 또는 같은 카드 재입력으로 확정 |
| 새 오브젝트 설치 | '빨간 길목 쪽 빈 곳에 놓으세요.' | 실제 설치 위치 확정 |
| 방향 지정 | '구체가 오는 쪽으로 방향을 정하세요.' | 실제 방향 확정 |
| 선택 기회가 더 남음 | '카드를 한 장 더 고르세요.' | 남은 선택을 모두 사용 |
| 웨이브 준비 | '웨이브를 시작하세요.' | 시작 버튼 또는 Space로 실제 시작 |

진행은 타이머나 안내 클릭이 아니라 실제 게임 상태 전환에 연결한다.
취소하면 해당 행동 단계로 돌아온다. 안내가 터치·드래그·버튼을 가로막지 않게 한다.
첫 판에도 두 번 고르는 현재 규칙을 유지한다. 첫 카드를 설치했다고 바로 웨이브 시작을 안내하면 안 된다.

첫 설치 중에는 겹치기·반응·15도 조준·다중 선택·웨이브 넘기기를 함께 설명하지 않는다.
모든 설명을 처음부터 자동으로 재생하지 않고, 필요한 순간 한 줄 안내와 '더 알아보기' 진입을 제공한다.

## 2. 기본 카드: 짧은 효과 문장을 남기기

기본 카드는 '이름 → 주효과 한 문장 → 설치/강화에 필요한 행동' 순서로 읽히게 한다.
아이콘과 색은 보조 단서다. 아이콘과 전문 용어만으로 효과를 설명하지 않는다.

아래는 교체 문구 제안이다. 구현 시 실제 효과와 대조해 확정한다.

| 카드 | 기존 기본 설명 | 제안 |
|---|---|---|
| 얼음 | ~~적중 빙결 / 형태 서리~~ | **냉기를 쌓아 구체를 잠깐 멈춰요.** |
| 땅 | ~~적중 기절 / 형태 턱~~ | **맞은 구체를 확률로 잠깐 기절시켜요.** |
| 별 | ~~적중 별빛 / 형태 끌림~~ | **주변 공격의 피해를 모아 폭발해요.** |

위 문장은 주효과를 설명한다. 얼음이 한 번 맞으면 반드시 멈춘다거나, 별이 직접 모든 공격을 강화한다고 오해시키면 안 된다.
수치·발동 조건·공격 모양에 붙는 성질·반응 전체는 '자세히'에서 확인하게 한다.
기본 설명은 뜻을 보존하는 길이를 우선하고, 실제 작은 화면에서 짧은 1~2줄을 목표로 다듬는다. 임의 말줄임으로 핵심 동사를 자르지 않는다.

15속성 전체에 대응하는 요약을 명시적으로 작성한다. '적중·형태'라는 두 개의 내부 분류를 처음부터 학습시키지 않는다.
공격방식·강화·발동·연계 카드도 효과의 주체·조건·결과를 잃지 않도록 같은 기준으로 검토한다.
예외 조건이 선택 결과를 크게 바꾸면 기본 화면에도 짧게 남긴다. 읽을 정보량을 줄인다는 이유로 선택에 필수적인 조건까지 숨기지 않는다.

## 3. 설명의 등장 시점과 우선순위

- 새 종류 해금: 기존 웨이브별 해금은 유지하고 해당 카드가 처음 등장했을 때 한 번만 짧게 안내한다.
- 겹치기: 처음부터 긴 규칙을 설명하지 않고, 기존 오브젝트에 놓으려는 순간 결과를 미리 보여 준다.
- 특수 반응: 실제 처음 만들어진 반응의 이름과 결과를 짧게 알려 준다. 반응표 전체를 강제로 읽히지 않는다.
- 보스·저항: 다음 웨이브 판단에 필요한 경고를 우선한다. 일반 조작 안내와 같은 위치에 여러 줄 쌓지 않는다.
- 도움말·설정·튜토리얼 목록은 언제든 직접 열 수 있게 한다. 익숙한 플레이어의 자세히 설정은 보존한다.

자동 모달 튜토리얼과 한 줄 안내가 같은 개념을 중복 설명하지 않도록 안내의 소유자를 하나로 정한다.
건너뛰기, 실제 행동 완료, 설명 열람은 서로 다른 상태다. 기존 device.cfg의 완료/열람 기록과 첫 판 해금 상태를 무조건 초기화하지 않는다.

## 첫 구현 범위

1. 일반 판의 최초 행동 안내와 첫 실행 진입을 바꾼다. 중도 취소·나가기·이어하기도 실제 행동 단계와 맞춘다.
2. 15속성 기본 카드에 주효과 요약을 제공하고 자세히 설명을 보존한다.
3. 새 카드 종류 안내의 중복 모달을 제거하고 필요할 때 설명을 여는 동선을 제공한다.

한 번에 첫 카드 종류·출현 확률·피해·난이도·선택 횟수까지 바꾸지 않는다. 예를 들어 별을 초반에서 빼는 것은 카드 노출/밸런스 가설이 추가되므로 별도 검증 대상으로 둔다.
계정 동기화나 전체 게임 UI 재설계도 이번 범위에 포함하지 않는다.

변경 대상은 tutorial.gd의 첫 진입/완료 처리, main.gd의 안내 큐·기본 카드 렌더링·상태 전환이다.
`docs/features.md`의 TUT·CARD·UI 명세와 같은 ID의 검사를 구현 커밋에서 함께 갱신한다.
기존 PR #6의 선택 헤더·터치 적용 버튼과는 독립적인 제안이다. 실제 구현 시 해당 PR의 병합 상태를 확인해 배치 충돌을 검토한다.

## 검증과 반증

구현 전 신규 플레이어에게 현재 버전으로 '첫 웨이브 시작'을 부탁하고, 멈춘 지점과 질문을 기록한다.
수정 버전에서는 같은 과제를 주되 같은 사람에게 이미 배운 문제를 반복시켜 향상됐다고 결론 내리지 않는다.
초기 탐색은 버전당 신규 플레이어 6명을 제안한다. 모집이 어렵다면 적은 수의 관찰은 탐색 결과로만 기록한다.

수정 전 테스트를 시작하기 전에 다음 잠정 기준을 확정한다.

- 목표: 수정 버전 6명 중 5명 이상이 설명자의 개입 없이 첫 웨이브를 시작하고, 자신이 고른 카드의 주효과를 자기 말로 설명한다.
- 기록: 첫 설치·첫 웨이브 시작까지 걸린 시간, 취소·오배치·효과 오해, 도움 요청, 자세히/도움말 사용. 시간은 앱 실행과 일반 판 시작 중 어느 시점을 기준으로 했는지 구분한다.
- 가드레일: 배치와 조준 실수, 필수 조건 오해, 버튼을 찾지 못하는 사례가 늘지 않아야 한다.
- 반증: 문장은 짧아졌지만 효과 설명이 틀리거나 잘못된 설치가 늘면 단순 축약안을 기각한다. 특정 카드만 이해가 안 되면 튜토리얼 전체보다 그 카드 설명부터 수정한다.

6명은 통계적 우월성이나 리텐션 개선을 입증하는 표본이 아니다. '건너뛰기율 감소'도 읽기 강제의 결과일 수 있어 성공 지표로 단독 사용하지 않는다.
현재 측정 데이터가 없으므로 개선 효과를 수치로 주장하지 않는다.

자동 검사는 상태별 안내 전환·취소·남은 선택·이어하기·기존 완료 기록·요약 누락·자세히 보존을 대상으로 한다.
화면 검사는 글자 100/130%, PC·터치, 폰 안전 영역·태블릿·넓은 화면에서 안내와 카드·적용 버튼의 관계를 본다.
문구 이해는 자동 검사나 봇으로 판정하지 않고 실제 플레이 관찰로 확인한다.

## 가장 강한 반론

초반에는 속성·공격방식·반응을 이해해야 하므로 설명을 늦추면 나중에 더 막힐 수 있다.
이를 피하려고 규칙을 삭제하지 않고 사용 순간의 결과 미리보기와 선택적인 상세 설명으로 옮긴다.
신규 플레이어가 기본 카드 문장을 잘 이해하면서도 설치·조준에서만 막힌다면, 카드 개편보다 입력 안내를 먼저 적용하는 편이 맞다.
