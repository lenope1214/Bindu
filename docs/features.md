# 기능 명세 (기대 동작 + 검사)

게임의 모든 기능을 한 줄씩 적고, 그 줄이 맞는지 무엇으로 확인하는지 짝지어 둔다. 배포 전에는 `tools/run.sh check` 한 번과 스크린샷 훑어보기로 "문서대로 동작하는지"를 확인한다.
플레이어용 자세한 설명(반응 91개 표, 조작 키 등)은 [README](../README.md), 수치는 코드(`scripts/rules.gd`·`pattern.gd`·`elem.gd`)가 원본이다. 이 문서는 "무엇이 어떻게 돼야 하나"만 적는다.

## 규칙: 기능을 바꾸면 여기도 같이

- 기능을 추가·변경·삭제하는 커밋은 이 문서의 해당 줄과 그 검사를 **같은 커밋에서** 고친다.
- 검사가 `spec`인 줄은 `tools/spec_check.gd`에 같은 id로 확인 코드가 있어야 한다. 없거나, 코드에만 있고 문서에 없으면 `tools/run.sh spec`이 실패한다.
- 새 기능은 되도록 `spec`으로 확인할 수 있게 쓴다. 자동으로 보기 어려운 것(손맛·화면 배치)만 `shot`·`수동`으로 둔다.
- id는 한 번 쓰면 바꾸지 않는다(지운 기능의 id는 다시 쓰지 않음).

## 검사 종류

| 이름 | 무엇으로 | 실패 판정 |
|---|---|---|
| spec | `tools/run.sh spec` (tools/spec_check.gd) | `FAIL <id>` 줄, 끝 코드 1 |
| path | `tools/path_test.gd` (그린 궤적) | `FAIL` 줄, 끝 코드 1 |
| fuzz | `tools/run.sh fuzz` 무작위 클릭·끌기·키·터치 | 시드별 스크립트 오류 1개 이상 |
| cont | `tools/run.sh cont` 4웨이브마다 끄고 이어하기 | `DIFF`·스크립트 오류 |
| online | `tools/online_check.gd` 패치 서명·기록 HMAC | `결과: 모두 통과`가 아님 |
| server | `cd server && pytest` | 실패한 테스트 |
| bot | `tools/run.sh bots`·`compare`·`modes` 밸런스 측정 | 판정 없음. 숫자를 바꿀 때 전후 비교 ([rule-history](rule-history.md)) |
| shot | `tools/shot.gd` 스크린샷을 눈으로 (글자 크기 1.0·1.3, touch) | 겹침·잘림·글 깨짐 |
| mp | 로컬 중개(`tools/mp_signal.gd`) + `tools/mp_conn_test.gd`·`tools/mp_play.gd` 두 프로세스 | `MPCONN FAIL`·`MPPLAY FAIL`, 대결 `MPW` 줄이 역할끼리 다름 |
| sync | `tools/sync_check.gd` 로컬 서버 + 기기 두 개 | 실패 줄 |
| update | `tools/update_check.gd` 서명·zip 확인 (실제 교체는 Windows에서 손으로) | 실패 줄 |
| 수동 | 사람이 직접 해 보기 | |

`tools/run.sh check` = spec + path + fuzz(4판) + cont(13웨이브) + online + server(파이썬 패키지가 있을 때). 화면 배치(shot)는 따로 본다.
