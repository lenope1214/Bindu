# 이어하기 요약 잘림: 600개 조합 비교

**문자 잘림은 150/600 → 0/600이다.** 전체 사용성 개선이나 PR 완료 판정은 아니다. [집계·소스 해시](summary.json), [전체 전후 값·검사 기록](comparison-records.jsonl), [관찰 도구](measure.gd), [실행 도구](run.py), [가설·원인](plan.json).

## 원인과 수정

PC의 좁은 이어하기 타일은 210×92였다. 기본 문구 ‘웨이브 13부터 · 평원 · 랭크’가 두 줄로 접히면 설명의 아래 끝은 버튼 안 좌표101이 되어 9px 잘렸다. VBox 최소 높이85와 기존 위아래 여백32를 합친117이 필요했다. 같은 문구의 넓은436px 타일은 한 줄로 들어갔다. 전체 UI/시작 화면 배율1.0에서도 재현돼 전역 축소나 일시적인 snapshot만으로 설명되지 않았다.

기존 HUD의 시작 화면 맞춤 경로에서 **보이는 이어하기 버튼**의 최소 높이를 자식 VBox 최소 높이+기존 여백으로 계산한다. PC92·폰170의 기본 높이를 보존하고 이전 높이를 누적하지 않아 글이 짧아지거나 폭이 넓어지면 다시 작아진다. 제품 스크립트 변경은 `hud.gd`4줄이다. 저장·문구·포커스·카메라 정책은 수정하지 않았다.

- 전후의 full raw JSON 값은 `comparison-records.jsonl`에 그대로 담았다. 각 입력의 경로·바이트·SHA는 summary에 있다. 원본 JSON과 캡처는 로컬에 보존한다.
- 정상 main 루프와 native macOS Window를 쓴다. 폰·안전 영역은 모의이며 프로젝트 기본 canvas stretch가 적용된다. 실제 iOS/Android·접근성·실기기 판정은 이 검사에 포함하지 않는다.

## 남은 읽기 품질과 검증 한계

현재 PC100 캡처에는 ‘랭크’가 ‘랭/크’로 갈라지는 낱말 줄바꿈이 남는다. 문자 잘림0은 단어 묶음·사람의 읽기 품질 통과를 뜻하지 않는다. 타일이 높아지면서 기존 시작 화면 자동 맞춤이 작동해 일부 PC 조건의 시작 화면 표시 배율은 기준보다 최대 약4.6% 작아졌다. 지정 UI 배율·일반 판 타일의 로컬 크기는 같고 전장 카메라 보존 검사는 통과했다. 이 두 읽기 품질 항목은 일시정지된 목표를 재개할 때 다룰 후속 범위다.

최초 `baseline-01`은 main 준비 전에 sfx에 접근한 QA 시작 오류다. 해당 소유 프로세스만 종료했고 [실패 기록](baseline-01/run.json)은 제외·보존했다. 이후 한 프레임을 기다린 `baseline-02`의 PC100 예비 측정은 유효하며 최종 전후 비교는03/current01이다. 원본 오류를 제품 실패로 세지 않았다.

## 공통 검사

[최신 전체 로그](full-check.log)는 exit0: 명세252, 전달 상태86, 전투345사례/4140표본, fuzz4개가 실제3000프레임 DONE/exit0, W4·8·12 복원과 W13 도달, runtime 경계0실패를 기록했다. **서버 검사는 system Python에 fastapi·pytest·httpx가 없어 건너뛰었다.** 이전 소스 단계의 서버28개 통과와 구분한다.

[일회성 아키텍처 감사](architecture.log)는 기존41개와 같고 새 실패0이다. 전체 감사 통과가 아니다. `_fit_panels`의 의도한 레이아웃 변경만 review 기록에 추가했다. 일부 전후 native 프로필의 ObjectDB2 종료 경고는 원본과 실행 집계에 남겼으며 해결했다고 주장하지 않는다.

이번 결과는 로컬 구현·검증 단위다. I-15 충돌 원인, I-17 접근성 누락, 고배속 지연·실기기·사람 과제와 PR Ready 조건은 남는다.
