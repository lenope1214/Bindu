# 실기기·사용자 과제의 남은 검증

상태: 준비만 됨. 실행 결과 없음. 사용자는 현재 실기기 연결이 어렵다고 답했다. 아래는 BF-44–50을 자동 검사 통과만으로 닫지 않기 위한 재개 지점이다. 특정 iPhone/Android·운영 빌드에서 성공했다고 주장하지 않는다.

별도 [로컬 혼합 소스 검사](multiplayer/mixed-version/README.md)는 실제 native WebRTC로 PC/폰 모의15actor426단언을 통과했다. 아래 실제 기기·인터넷·사람 과제의 실행 결과로 합산하지 않는다. 배포된 구release 바이너리 조합과 실기기/멀티 예약의 OS kill 후 앱 재실행은 여전히 미검증이다.

별도 [실제 iOS Simulator 검사](ios-runtime/README.md)는7상태의 UIKit 앱 전환·native 재개·실제 프로세스 종료/새 PID 이어하기를 통과했다. custom debug 싱글 QA이며, 아래 실기기 잠금·전화·Jetsam·Android·물리 손가락·멀티 검증은 남는다.

[기술 조작부의 native iOS 후속](ios-layout/README.md)은5배율302장면의 정보창/선택 안내/기술 가림과 첫 표면, 실제 터치12단언을 검증했다. 아래 실기기·사람·접근성 과제는 닫지 않는다. I-08은 [별도 첫 실행 수정](mobile-default/README.md)에서 실제 cold16개로 확인했고, I-09/I-11은 [수치](inspector-reading/README.md)와 [예시](attack-preview/README.md)의 별도 단계에서 처리했다. 이 로컬 결과를 아래 실기기/사람 과제 완료로 합산하지 않는다.

기기 연결 후 저장을 분리한 시험 빌드와 재현 가능한 판을 사용한다. 전장 크기·카메라 배율·피해·사거리·공격 순서는 유지한다. 기기/OS/빌드 SHA·화면 배율·연속 촬영·실제 실행 순서와 관찰을 기록한다. 이전/이후 비교는 같은 초기 상태·과제로 맞추며, 익숙해진 효과를 제품 효과와 섞지 않는다.

성공률·완료시간·오적용·상태 설명 정확도를 원자료로 남긴다. 목표 수치나 참가자 수는 아직 합의하지 않았으므로 임의 숫자를 출시 기준으로 만들지 않는다. 코드 결함은 재현 → 최소 수정 → 같은 과제 재검증으로 처리하고, 물리 가림·인지 과제는 실제 관찰 후 개입을 결정한다.

키보드 후속의 [선택한 읽기/복귀 경로](keyboard/README.md)는 PC100/130·폰130 모의 화면의 실제 가상 GUI 키126단언으로 확인했다. 이 결과는 위 BF-50의 스위치·스크린리더·색각/대비·전체 전장 과제를 대체하지 않는다.
