# 겹침 클릭 진단

예상: 같은 위치의 UI 버튼·칩·전장 오브젝트 중 앞에 있는 한 대상만 누름/뗌 한 쌍을 소유한다.

관찰 전 가설:
1. 상태/입력: 전장 hit test가 UI 사각형을 빠뜨려 실제 Button 입력도 전장으로 흐른다. PC/터치 버튼 위 오브젝트에서 버튼 횟수와 selected/phase를 함께 기록한다.
2. 순서: 버튼 콜백이 패널을 숨긴 뒤 같은 release가 전장 동작을 확정한다. cancel/fold처럼 가시성을 바꾸는 버튼을 누르고 phase·picks·target 변경을 기록한다.
3. 에뮬레이션: ScreenTouch에서 흉내 낸 mouse press와 원래 touch의 칩/배지 처리기가 서로 독립적으로 동작한다. 같은 겹침을 PC, 터치 에뮬레이션 on/off로 비교하고 UI pin·버튼 callback·전장 선택을 동시에 기록한다.

각 경우 반복 3회. OS 입력 없이 VirtualInput을 사용한다. 겹침 조건은 실제 버튼 위치에 전장 오브젝트를 두고, 같은 좌표의 그려진 칩 사각형을 고정해 재현한다.

관찰: 정상 PC Button은 3/3에서 버튼 1회·선택 0. 터치 Button/배지 겹침은 3/3에서 버튼 1회와 pin=0이 함께 발생했다. 배지/오브젝트 겹침은 에뮬레이션 on에서 3/3 선택=1·pin=0, off에서는 3/3 선택=0이었다.

원인: 실제 Button의 일반 GUI 전파 실패나 단순 release 시점 가시성 변경이 주원인은 아니다. 직접 그린 정보 UI는 버튼보다 먼저 ScreenTouch를 처리하며, 그 이전/이후 에뮬레이션 마우스는 별도로 전장 입력에 도달했다. 정보 UI hit test와 두 이벤트 스트림의 소유권이 분리되어 있었다.

수정 후 같은 12개 표본은 모두 단일 대상만 처리했다. 실제 버튼 → 정보 칩/배지 → 전장 순으로 중재하고, 원래 터치와 마우스의 release를 각각 소비한다. 드래그를 UI 위에서 놓으면 원위치로 취소하며 모달 밖 클릭도 창만 닫는다. 테스트는 OS 입력 없이 동일 runner에서 실행했다.
