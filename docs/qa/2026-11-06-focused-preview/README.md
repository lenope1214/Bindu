# 활성 오브젝트에 집중한 공격 미리보기

- 주변 오브젝트 사본은 배치 보너스 계산에만 사용하고 숨긴다. 공격은 활성 오브젝트만 실행한다.
- 미리보기의 보조 공격과 보조 공격 안내 줄을 제외했다. 실제 게임의 보조 공격은 그대로다.
- 속성 칩은 이름·레벨을 생략하지 않고 줄바꿈한다. 미리보기 높이 180, 렌더링 배율을 키워 본체·탄·명중·특수 효과를 더 크게 보여 준다.
- 적이 죽거나 본체 뒤/화면 밖으로 나가면 0.35초 간격으로 부족한 표적을 보충한다. 오브젝트의 누적 발동 상태는 유지한다.
- 주변 오브젝트의 직접 공격이 필요한 발동은 이 단일 오브젝트 장면에서 강제로 만들지 않는다. 활성 오브젝트 자체의 실제 발사·명중·조합 처리를 사용한다.

## 확인

PC 100%, 폰 모의 환경 130%에서 주변 오브젝트 숨김·공격 제외·보조 공격 제외, 속성 5개 줄바꿈, 16초 연속 명중/표적 보충을 확인했다. [PC](pc.png), [폰](phone.png), [PC 로그](pc.log), [폰 로그](phone.log).

15개 공격방식 렌더링과 분사·물줄기·레이저·음파·시계침·일식 픽셀 검사를 통과했다. [렌더링 로그](gallery.log).

기존 수치 대조 도구는 내부 전체 전투 모드로 같은 전투 커널을 검증한다. 실제 표시 모드는 기본적으로 단일 공격·보조 공격 제외이며 별도의 표시 검사로 검증한다. 실기기 검증은 하지 않았다. native 도구 종료 시 기존 ObjectDB 잔존 경고가 있으며 실행 중 SCRIPT ERROR는 없다.

전체 check의 명세 238개·기본/처치 대조·튜토리얼·무작위 입력 4시드·이어하기·통신 검사 통과: [로그](check.log). 이후 전장 바깥을 향한 오브젝트도 예시 표적을 맞히도록 미리보기의 경계만 넓혔으며, [최종 폰 모의 검사](final-phone.log)와 [최종 명세 238개](spec.log)를 다시 통과했다. 실제 전투의 전장 경계는 유지한다. 서버 Python 검사는 의존성 부재로 생략했다.
